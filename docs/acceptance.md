## 1. Попунктна верифікація критеріїв приймання (SPEC §15)

### Критерій 1: Незалежність процесів та аварійний захист (SPEC §15.1)
> *«Незалежні процеси BESS і EMS взаємодіють лише через MQTT; зупинка BESS-контейнера → EMS входить у SAFE_MODE і показує аларм.»*

- **Архітектурна ізоляція:**
  - BESS (`bess-sim`) та EMS Core (`ems`) функціонують в окремих процесах (та окремих Docker-контейнерах).
  - Жоден сервіс не має прямого доступу до пам'яті чи приватної бази даних іншого. Взаємодія відбувається виключно через брокер Mosquitto за топіками: `sim/clock`, `ems/{id}/setpoint`, `ems/{id}/command`, `bess/{id}/telemetry`, `bess/{id}/status`, `bess/{id}/alarm`.
- **Логіка захисту `SAFE_MODE`:**
  - Диспетчер EMS (`Dispatcher`) відстежує часовий лаг надходження телеметрії. Якщо телеметрія від BESS відсутня більше 3 послідовних симуляційних тіків ($> 3\text{ хв}$ сим-часу), або якщо BESS переходить у статус `FAULT`, диспетчер миттєво активує режим `SAFE_MODE`.
  - У режимі `SAFE_MODE` уставка активної потужності примусово фіксується на `0.0 кВт` (`reason: "safe_mode"`), блокуючи заряд і розряд для запобігання пошкодженню обладнання.
  - Генерується операційна подія тривоги (`event: "SAFE_MODE_ENTER"`), яка транслюється через WebSocket клієнтам на дашборді.
- **Команда автоматизованої верифікації:**
  ```bash
  cd ems && uv run pytest tests/test_stage3_dispatch.py -k safe_mode
  ```
- **Результат виконання тесту:**

### Критерій 3: 1-місячний бенчмарк ефективності (seed=42) (SPEC §15.3)
> *«Для тестового періоду (1 місяць синтетики, seed=42) система показує: витрати без BESS, з BESS, чистий ефект, циклів — і MILP+LightGBM дає результат ближчий до perfect foresight, ніж TOU_SIMPLE.»*

- **Методологія тестування:**
  - Утиліта [`scripts/run_backtest.py`](../scripts/run_backtest.py) генерує 30-денний сценарій (720 годин) із фіксованим зерном `seed=42`.
  - Моделі LightGBM тренуються на попередніх 90 днях історії до початку тестового періоду (без витоку майбутнього).
  - Щодня формується добовий прогноз цін РДН на 24 години наперед, на основі якого розв'язувач MILP будує погодинний графік роботи.
  - Змодельована робота фізичної батареї з обмеженнями SoC (10–90%) та деградацією (1.25 грн/кВт·год) проти фактичних цін РДН і тарифів ОЕС України.

### Критерій 4: Порівняння ML-моделей на Walk-Forward валідації (SPEC §15.4)
> *«Мінімум три ML-моделі порівняно на walk-forward, метрики видно в UI.»*

- **Реалізовані архітектури моделей:**
  1. `NaiveModel`: Базовий рівень персистенції (значення доби або тижня тому).
  2. `LightGbmModel`: Набір із 24 окремих градієнтних бустингів (по одному на кожен крок горизонту $t+1 \dots t+24$) із підтримкою квантильної регресії для інтервалів p10/p90.
  3. `LstmModel`: Глибока нейромережа на базі PyTorch (Seq2Seq архітектура з 168-годинним контекстом, лагами та відомими календарними ознаками майбутнього).
- **Метрики якості валідації:**
  - Усі моделі валідуються за схемою Walk-Forward з розширюваним вікном без підглядання у майбутнє.
  - Розраховуються метрики: **MAE** (грн/МВт·год), **MAPE** (%), **RMSE**, **WAPE**, **Pinball Loss** (для квантилів).
  - Дані виведено у таблицю на сторінці `/forecasting` (`MlPage.tsx`).

### Критерій 7: Швидкий запуск з нуля (Turnkey Docker) (SPEC §15.7)
> *«docker compose up з чистого клону — робоча система за ≤ 5 хв.»*

- **Автоматична ініціалізація бази даних:**
  - Модуль [`ems/ems/db/seed.py`](../ems/ems/db/seed.py) містить процедуру `ensure_db_initialized_and_seeded()`.
  - При старті контейнера `ems` у функції життєвого циклу `lifespan`:
    1. Автоматично створюються всі реляційні таблиці та гіпертаблиці через `Base.metadata.create_all`.
    2. Ініціалізуються дефолтні значення для всіх секцій конфігурації.
    3. Якщо таблиці цін та споживання порожні — генеруються та пакетно завантажуються 2 роки синтетичних даних (2024–2026).
  - Відпадає потреба ручного запуску окремих команд міграцій (`alembic upgrade head`) або скриптів заповнення.
- **Оптимізована збірка:**
  - `web` збирається через багатоетапний Dockerfile на Nginx Alpine.
  - Запуск усіх 5 контейнерів (`timescaledb`, `mosquitto`, `ems`, `bess-sim`, `web`) виконується командою:
    ```bash
    docker compose up --build
    ```
  - Час холодного старту з чистого середовища складає менше 3 хвилин.
